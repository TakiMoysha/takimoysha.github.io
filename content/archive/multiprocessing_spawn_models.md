При запуске любой программы OS создает новый процесс. В unix-like системах эта процедура работает как кобинация системных вызовов `fork()` и `exec()`.

**Процесс** это просто исполняемый файл, набор инструкций, при исполнении которому назначаеться своя память, стек, дескрипторы и PID.

#### Fork/Exec - основной механизм
При форке OS создате child текущего процесса, копирует переменные, память, стек, открытые файлы и другие ресурсы. Дочерний процесс выполняется в той же точке кода на которой произошел `fork`. При этом операция возвращае:
- pid child процесса для родительского;
- `0` для дочернего процесса;
- `-1` в случае ошибки.

> [!quote] Everything is a File - Unix's Philosophy

**Почему не создавать файл с нуля?** Unix задизайнен по принципу "все есть файл", включая input/output вроде терминала или ресурсов вроде сокетов. Так, если мы создает процесс с нуля, например команду в терминале, она не будет знать о родителе и потребует повторного открытия файла для выполнения, что избыточно. Как дочерний процесс, команда будет знать об открытом терминале, что упростит вывод в него и т.д.

Новый процесс требует своей памяти, новый стек, переоткрытия файлов, подтягивания оружения и разрешений. Родительсий процесс все это уже знает и его дочка может это просто переиспользовать, что быстрее и эффективнее.

**Модификация дочернего процесса**. В большинстве случаев м не хотим точкую копию родителя, мы хотим запустить другую программу. При первом копировании родителя, мы получаем "чистую копию", которую мы можем "поправить" перед запуском программы: изменить workdir; закрыть не требуемые файлы наследуемые от родителя; установить env переменные для новой программы.

Итого: `fork`создает копию процесса, а `exec` заменяет копию на новую программу.

**Copy-on-Write**. Современные ОС используют модель COW для создания дочек. Суть в том, что копирования происходит только по требованию записи. Например, все родительские env переменные требуются для процесса только для чтения, они будут только прочитаны без дублирования. ОС при `fork` операции помечает как иммутабельную "read-only" страницу и разделяет ее между родителем/наследником. При попытке записать что-то в нее, ОС копирует требуемую часть для родителя/наследника оставляя оригинал не тронутым.

**Если мы копирует данные, почему выполняется другая программа?**. После копирования памяти вызывается команда `exec` (`execve`, `execl`), которая стирает всю память (код, данные, стек), заменяет их на даннеы, которые  требуются для переданной программы. При этом PID остается тот же.

#### pthread_create - альтернатива fork

`pthread_create()`  создает вместо процесса новый поток для родителя. Потоки делят память, адреса и дескрипторы. Но у каждого потока свой стек и регистры. Обычно создать поток быстрее, чем сделать `fork` процесса, т.к. вообще не требует копирования. Но потоки *не изолированы* - ошибки в одном потоке могут повлиять на весь процесс.

#### posix_spawn

`posix_spawn()` - современный свособ запустить процесс. Объединяет ф-ционал `fork` + `exec` в одном вызове. Может избегать полного копирования памяти (зависит от реализации, особенно в embedded системах). Позволяет задавать параметры запуска до создания процесса, тут же может задать настройку дочернего процесса.

При этом, это отдельный системный вызов, а не обертка над `fork+exec`. Он обходит проблему копирования памяти (состояние потоков, залоченых мьютексов, etc.) и избегает опасностей `fork` в многопотоке.
