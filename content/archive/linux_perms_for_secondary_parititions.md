Установка разрешений на диск без привязки к пользователю и без `umask=000`.

> Это полезно не только в multitenant-системах, это общий подход, что бы диск монтировался в независимости от самого пользователя, а был частью системы, при это давал права работать с ним пользователям.

Проблема с *ext4 - не хранит владельца/группу с собсвенных метаданных*, их не получиться указать в fstab. Для ext4 необходимо указать права на самом диске, т.к. метаданные прав храняться на самой fs:
```shell
# рекурсивно меняем группу
chgrp -R <group_name> /run/media/devlab-storage
# рекурсивно добавляет групповые права
# g+r - читать
# g+w - писать
# g+X - исполнять (только если уже есть это право у кого-то)
chmod -R g+rwX /run/media/devlab-storage
# ставит group на сам каталог, то есть будут наследоваться каталога, а не создателя
sudo chmod g+s /run/media/devlab-storage
```

Формат записи `fstab`:
```apache
LABEL=linux-home /run/media/takimoysha/linux-home   ext4   defaults  0 0
LABEL=storage    /run/media/takimoysha/secondary    ext4   defaults  0 1
LABEL=storage    /run/media/devlab-store            ext4   defaults,gid=1001  0 2
```

Последнии цифры dump и pass:
**Для dump (резервное копирование)** обычно ставиться 0 и 1 если используется утилита dump. 
**Для pass (проверка при загрузке)** ставиться для проверки диска: 1 проверять в первую очередь (корень системы, должен быть один в fstab), 2 проверять после первых, 0 - не проверять. Для сетевых, swap ставиться 0. Для btfs можно 0, он использует свои приколы.

Места для монтирования в linux:
- `/mnt` — традиционное место для временных монтирований (кратковременные тесты), но допускается и для постоянных точек: /mnt/devlab-store
- `/media` — обычно используется для автоматически монтируемых сменных носителей (подкаталоги с именами пользователей), но для системных дисков тоже можно: /media/devlab-store
- `/srv` — для данных сервисов (например, если диск используется службой): /srv/storage
- `/opt` или `/var` — только если диск служит для конкретных приложений (/var/lib/..., /opt/appdata)
- `/data`, `/storage` — часто встречающиеся нейтральные имена, если хотите явную точку для общих данных: /data, /storage, /srv/storage
- для общих дисков используют корневые нейтральные точки вроде /srv, /data или /storage. Это явно говорит: диск — ресурс для системы/сервиса, а не «домашняя» папка пользователя.

**Access Control List (ACL)** - расширение классической модели unix-прав (u/g/o). Можно устанавливать точечный доступ, задавать права произвольным пользователей и групп, устанавливать "наследуемые" ACL на каталоги. `setfacl`.

Для **btrfs** хранит unix и ACL метаданные в самой fs и работают так же как и в *ext4*.
